## Запуск проекта

### 1. Клонирование репозитория

```bash
git clone https://github.com/ViktorBelik/check_luck.git
cd check_luck
```

### 2. Настройка переменных окружения

Создать файл `.env` на основе `.env.example`.

В `.env` необходимо указать параметры Django, PostgreSQL и период проведения акции.

Пример:

```env
DEBUG=True
LOGLEVEL=DEBUG

SECRET_KEY=secret-key

POSTGRES_DB=check_luck
POSTGRES_USER=postgres
POSTGRES_PASSWORD=postgres
POSTGRES_HOST=db
POSTGRES_PORT=5432

PROMO_START=2026-10-01T00:00:00+03:00
PROMO_END=2026-12-31T23:59:59+03:00
```

> Для production-окружения необходимо использовать собственные безопасные значения `SECRET_KEY` и пароля PostgreSQL.

### 3. Запуск Docker Compose

```bash
docker compose up --build
```

### 4. Применение миграций

Если миграции не выполняются автоматически:

```bash
docker compose exec backend python manage.py migrate
```

### 5. Создание пользователя

```bash
docker compose exec backend python manage.py createsuperuser
```

После этого приложение доступно через настроенный Docker-порт.

## Реализовано

### Регистрация чека

* Авторизация пользователя.
* Регистрация чека через форму.
* Проверка ФН, ФД и ФП.
* Проверка даты покупки на попадание в период акции.
* Проверка минимальной суммы покупки — 1000 рублей.
* Проверка уникальности комбинации ФН + ФД + ФП.
* Новый чек создаётся со статусом `pending`.
* Ошибки валидации отображаются пользователю без HTTP 500.

### QR-код

Реализована загрузка изображения QR-кода с чека.

После распознавания QR-кода автоматически заполняются:

* ФН;
* ФД;
* ФП;
* дата и время покупки;
* сумма покупки.

Для декодирования QR-кода используется библиотека `jsqr`.

Парсер поддерживает несколько распространённых форматов даты и приводит полученное значение к формату, подходящему для поля `datetime-local`.

Ручной ввод данных также остаётся доступным.

### Личный кабинет

* Отображаются только чеки текущего пользователя.
* Отображаются дата покупки, статус, сумма, дата регистрации и информация.
* Реализована пагинация по 10 чеков.
* Реализована сортировка по столбцам.
* Добавлено состояние кабинета без зарегистрированных чеков.
* Реализована адаптация интерфейса для мобильных устройств.

### API

Реализован единственный API endpoint:

```text
GET /api/receipts/
```

API возвращает только чеки текущего авторизованного пользователя.

Переданный через query-параметры идентификатор другого пользователя не позволяет получить его чеки.

Поддерживается сортировка:

```text
/api/receipts/?sort=amount&order=asc
```

Доступные поля сортировки:

* `purchase_date`;
* `status`;
* `amount`;
* `registration_date`;
* `information`.

### Frontend

* React-интерфейс регистрации чека.
* React-интерфейс личного кабинета.
* Клиентская валидация формы.
* Обработка серверных ошибок.
* Экран успешной регистрации.
* Загрузка QR-кода с автоматическим заполнением формы.
* Адаптивная версия для мобильных устройств.

## Архитектурные решения

### Django отвечает за backend-логику

В Django реализованы:

* модели;
* формы и серверная валидация;
* авторизация;
* регистрация чеков;
* API;
* работа с PostgreSQL.

### React отвечает за интерфейс

React используется для:

* формы регистрации;
* клиентской валидации;
* обработки запросов;
* личного кабинета;
* сортировки и пагинации;
* отображения состояний интерфейса;
* автоматического заполнения формы после распознавания QR-кода.

### Защита от получения чужих чеков

API не доверяет идентификатору пользователя из query-параметров.

Выборка формируется на основе текущего авторизованного пользователя:

```python
Receipt.objects.filter(user=request.user)
```

Поэтому передача другого `user_id` не позволяет получить чужие чеки.

### Защита от дубликатов

Проверка уникальности выполняется на уровне Django Form.

Дополнительно в базе данных используется уникальное ограничение для комбинации:

```text
FN + FD + FP
```

Это позволяет защитить данные не только на уровне пользовательского интерфейса, но и на уровне базы данных.

### Обработка QR-кода

Распознавание QR-кода выполняется на стороне frontend.

Из изображения QR-кода извлекается строка с параметрами чека. Затем отдельный parser преобразует эти данные в значения формы.

Такой подход позволяет отделить:

1. распознавание изображения;
2. разбор параметров QR-кода;
3. заполнение формы.
